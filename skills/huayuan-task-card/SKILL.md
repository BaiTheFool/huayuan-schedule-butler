# 华园任务卡技能

把非结构化的校园页面内容（课表、作业列表、考试安排、通知、邮件）转换为可追溯、可修改、可解释的任务卡，并据此排程。

## 何时使用

- 需要把某个平台的课程 / 作业 / 考试 / 通知整理成任务卡
- 需要判断两条任务是否为重复
- 需要生成或重排「今日 / 未来七天 / 本周」计划
- 需要解释某次排程调整的原因

需要登录的网页数据必须先由 `huayuan-browser-session` 完成会话检查与授权读取；本技能只负责把已经读取的数据转换为任务卡，不自行启动浏览器或保存认证信息。

## 核心数据模型：任务卡（11 字段）

字段顺序固定，不允许省略。缺失信息填 `待确认`，并把该条加入待确认清单。

| # | 字段 | 取值规则 |
|---|------|---------|
| 1 | 来源平台 | 教务系统 / eCourse / 雨课堂 / 学堂云 / 校园通知 / 邮箱 / 课程群 / 用户手动添加；合并时用 `、` 连接多个来源 |
| 2 | 课程或事项 | 课程全称；非课程事项写事项归属（如"研究生院通知""学院教务办"） |
| 3 | 标题 | 页面上的原始标题，不改写；过长可截断但另存完整标题在哪 |
| 4 | 任务类型 | 仅限：课程 / 作业 / 实验 / 报告 / 考试 / 测验 / 阅读 / 小组任务 / 报名 / 通知待办 / 个人安排 |
| 5 | 截止时间 | `YYYY-MM-DD HH:mm`；只有日期写 `YYYY-MM-DD（无具体时刻）`；无则 `待确认` |
| 6 | 提交方式 | 平台提交 / 邮箱 / 纸质 / 课堂 / 线下 / 未说明；`未说明` 归入待确认 |
| 7 | 所需材料 | 从页面文字提取的文件名、软件、教材章节；没有原文依据写 `待确认`，不要凭课程名推测 |
| 8 | 预计耗时 | 分钟数，给出区间（如 90-120）；基于任务类型基线表，允许用户覆盖 |
| 9 | 优先级 | P0 今天必须动 / P1 本周内 / P2 有余力 / P3 可选。规则见下方 |
| 10 | 置信度 | 高 / 中 / 低，判定规则见下方 |
| 11 | 来源摘录 | 页面原文片段，≤80 字，用于让人回去核对 |
| 12 | 状态 | 未开始 / 进行中 / 待确认 / 已完成 / 已取消 / 已顺延 |

### 优先级判定（按顺序匹配，命中即停）

1. 截止时间 ≤ 24 小时 且 预计耗时 ≥ 60 分钟 → P0
2. 考试、实验报告的截止 → P1 起（若 ≤72 小时则 P0）
3. 任务类型为「报名」「通知待办」且有明确截止 → P1（这类漏了代价高）
4. 截止时间在本周内 → P1
5. 截止时间在七天后 → P2
6. 无截止时间的阅读 / 通知类 → P3

### 置信度判定

| 置信度 | 条件 |
|--------|------|
| 高 | 页面明确写出该字段；多来源一致 |
| 中 | 页面有该信息但表述模糊（如"下周交"），或多来源表述不完全一致 |
| 低 | 只能从课程名、上下文章节、既往习惯推断 —— **必须进待确认清单** |

## 去重合并规则

判定为同一任务需同时满足至少两条：
- 同一课程（课程代码或全称一致）
- 标题相似度明显（去标点后有 60% 以上字符重叠，或含同一关键词如"实验报告二"）
- 截止时间相差 ≤ 24 小时

处理方式：
- 证据充分 → 合并为一张任务卡，来源平台列全部平台，来源摘录保留各平台原文（用 `；` 分隔）
- 证据不足 → **保留两条**，都标 `待确认`，在清单中写"疑似与 XX 重复，请确认以哪个为准"
- 严禁删除用户的任何条目；去重只是合并展示，原始条目始终可回溯

## 排程算法（可解释）

### 输入
- 固定占用：课程、考试、已确认的线下事项（不可移动）
- 任务池：所有未完成、未取消的任务卡
- 个人安排：带可移动性（固定 / 可微调 / 灵活）与保护等级
- 偏好参数：每日可用时段、单日负荷上限（默认 240 分钟）、缓冲时长（默认 20 分钟）、不可用时段（如 23:30 后不排）

### 生成顺序
1. 铺骨架：固定占用按时间填入七天网格
2. 排 P0/P1：按截止时间升序，每个任务**倒推**至少在其截止前 1 个可用时段完成；同一课程的多个任务尽量相邻放置
3. 插入个人安排：固定类优先占位，灵活类填入剩余空档
4. 排 P2/P3：只填剩余空位，不挤占缓冲
5. 加缓冲：任务之间插入缓冲；连续深度任务后加 30 分钟休息
6. 校验：单日负荷超上限 → 把最低优先级任务顺延到最近的空档，并记录顺延原因

### 输出三档
- **今日**：按小时的时间块（含固定课程、任务、个人安排、休息）
- **未来七天**：按天概览（每天 3-5 条关键事项 + 当日负荷分钟数）
- **本周**：按周概览（截止分布、负荷分布、风险提示：哪天过载、哪项可能来不及）

### 调整解释格式

每次重排输出变更对照表：

| 事项 | 原安排 | 新安排 | 原因 |
|------|--------|--------|------|
| 实验报告二 | 周四 20:00-21:30 | 周三 19:00-20:30 | 因为周四下午新增固定课，且缓冲需保留，前移到最近的六十分钟空档 |

原因必须写成「因为…所以…」，指向具体约束（固定占用 / 截止时间 / 负荷上限 / 用户偏好 / 缓冲规则），不允许写"优化了一下"这类空话。

## 待确认清单格式

```
待确认项（共 N 条）
1. [课程名] 标题 — 缺什么 — 建议确认路径：去哪里看 / 问谁
```
