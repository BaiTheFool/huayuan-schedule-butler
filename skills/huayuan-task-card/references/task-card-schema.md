## 字段填写细则

### 来源平台
- 单平台：`eCourse`
- 合并后：`eCourse、课程群`
- 降级路径产生：`用户提供`
- 可以精确到子页面时写上，如 `eCourse - 数据结构与算法 - 作业区`

### 截止时间
- 有具体时刻：`2026-10-30 23:59`
- 只有日期：`2026-10-30（无具体时刻）`
- 有相对表述：`待确认`，原文写进来源摘录
- 跨天任务（如开放时间窗）：`2026-10-28 08:00 至 2026-11-03 23:59`

### 提交方式
只从以下取值选，找不到依据就 `未说明`：
`平台提交` / `邮箱` / `纸质` / `课堂` / `线下` / `未说明`

### 所需材料
- 只列页面**明确出现**的文件名、软件、章节
- 页面写了"按模板"但没给模板 → 材料写 `待确认（页面提到模板但未给链接）`
- **禁止**根据课程名推测（如不要因为"物理实验"就自动补"实验报告模板"）

### 预计耗时
用区间。没有特殊依据时套用 `load-baseline.md` 的基线，并在计划里说明"按基线估算，可改"。

### 状态流转
```
未开始 → 进行中 → 已完成
未开始 → 已顺延 → 进行中
任意 → 已取消（用户明确取消）
置信度低 → 待确认（用户确认后回到未开始）
```

## 批量任务卡的展示方式

超过 5 条时，先给一张**汇总表**（只含：课程 / 标题 / 截止时间 / 优先级 / 置信度 / 来源平台），再对 P0 与待确认项单独展开完整 12 字段。

这样既保证可扫读，又保证关键项可追溯。
